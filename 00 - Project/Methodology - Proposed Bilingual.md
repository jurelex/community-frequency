# Community Frequency — Methodology / Metodología

## English

### Objective
The purpose of the methodology is to produce evidence that can be repeated, compared, and interpreted responsibly.

### Experimental principles
- Measure before making claims.
- Record both successful and unsuccessful tests.
- Separate observation from interpretation.
- Record enough context to reproduce a test.
- Treat preliminary findings as preliminary.
- Do not confuse hop count with physical distance.
- Do not treat packet delivery as proof of a complete route.
- Correlate node identities independently before assigning meaning to a path.
- Keep technology-specific observations separate from project-wide conclusions.

### Minimum test record
Where available, record date/time, technology and hardware, firmware/software version, test configuration, mobility/fixed status, RF parameters, RSSI/SNR, hop count, delivery/ACK result, path information, environmental context, limitations, and anomalies.

### Public release
Public documentation must be sanitized before publication. Credentials, private keys, passwords, sensitive GPS coordinates, private network configuration, personal contact information, and other sensitive operational information are excluded.

## Español

### Objetivo
El objetivo de esta metodología es producir evidencia que pueda repetirse, compararse e interpretarse de manera responsable.

### Principios experimentales
- Medir antes de hacer afirmaciones.
- Registrar tanto las pruebas exitosas como las que no tuvieron éxito.
- Separar las observaciones de las interpretaciones.
- Registrar suficiente contexto para poder repetir una prueba.
- Tratar los hallazgos preliminares como preliminares.
- No confundir el número de saltos (hops) con la distancia física.
- No considerar la entrega de un paquete como prueba de una ruta completa.
- Correlacionar de manera independiente las identidades de los nodos antes de interpretar una ruta.
- Mantener separadas las observaciones específicas de cada tecnología de las conclusiones generales del proyecto.

### Registro mínimo de una prueba
Cuando esté disponible, registrar fecha/hora aproximada, tecnología y hardware, versión de firmware/software, configuración, estado móvil/fijo, parámetros RF, RSSI/SNR, número de saltos, entrega/ACK, ruta, contexto ambiental, limitaciones y anomalías.

### Publicación
La documentación pública debe ser sanitizada antes de publicarse. Se excluyen credenciales, claves privadas, contraseñas, coordenadas GPS sensibles, configuración privada de red, información personal de contacto y otra información operativa sensible.
